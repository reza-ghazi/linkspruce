## Supported Chrome versions

- `minimum_chrome_version: "134"`, because root discovery needs `folderType` and `syncing`. Older builds fall back to discovery by position in code, but they are not supported.
- On-device AI requires a Chrome build with the Prompt API (stable channel, with feature badges for Chrome 138+). Availability is detected at runtime.
- Development and tests used Chrome 156 (installed) and Chromium 156 (Playwright).

## Material decisions

1. **TypeScript (strict, `erasableSyntaxOnly`) + esbuild + Vitest + Playwright.** No UI framework: there is a small DOM helper (`src/ui/shared/dom.ts`) that renders every untrusted value with `textContent`. The release bundle has minified whitespace and syntax but keeps readable identifiers for Web Store review. Source maps are excluded.
2. **Pure core, thin adapters.** All logic lives in `src/core/*` against the `BookmarksApi` and `KeyValueStore` interfaces (`src/core/platform.ts`). The service worker (`src/background`) and pages (`src/ui`) inject the real `chrome.*` implementations. Tests inject faithful fakes (`tests/helpers/fake-chrome.ts`), and real-Chrome E2E runs confirmed their fidelity: one discrepancy (move-index bounds) was found and fixed.
3. **Durable jobs instead of keepalive.** `JobRunner` (`src/core/jobs.ts`) persists items, cursor, leases, retries and counters in `chrome.storage.local`. Worker death leaves expired leases, which are reconciled to retries. Wake-ups come from `chrome.alarms` (30 s minimum) or from an in-worker timer for near-term work while the worker is alive. Processing is at-least-once and processors are idempotent.
4. **No offscreen document.** HTML metadata (title, canonical, base, meta tags, challenge and login signals) is extracted from a bounded byte prefix with an inert regex tokenizer (`src/core/audit/html-meta.ts`). Nothing is rendered and no subresources load. This avoids the `offscreen` permission entirely. `LanguageModel` is exposed in extension service workers in Chrome 156 (verified by probe), so on-device AI runs in the worker when the model is already available. Model download is started from a dashboard click, because it needs user activation.
5. **Storage: `chrome.storage.local` + `unlimitedStorage`.** Snapshots of 25k bookmarks take about 3.2 MB each and up to 12 are kept, which with caches exceeds the 10 MB default quota. Large per-bookmark maps are sharded (64 shards). Large values are chunked. `unlimitedStorage` has no install warning.
6. **Permissions.** `bookmarks`, `storage`, `unlimitedStorage` and `alarms` are required. `https://*/*` and `http://*/*` are **optional** host permissions, requested by a user gesture for online audits (broad, or scoped to the sites in a folder) and for the Gemini endpoint only. There are no content scripts, no history, cookies, debugger, tabs, offscreen, downloads or notifications permissions. Downloads use `<a download>` with a Blob from the dashboard.
7. **Network audits.** HEAD first, then a bounded GET (256 KB, streamed and cancelled) when HEAD is rejected or inconclusive, or when HTML metadata is wanted. Requests use `credentials: 'omit'`, `no-store` and `no-referrer`. The scheduler allows at most 5 requests globally, 1 per origin by default (maximum 2), with configurable spacing, `Retry-After` cooldowns, exponential backoff with jitter, and an `AbortController` timeout of 25 s or less. That stays under the 30 s fetch limit in the worker. Only the final URL and the `redirected` flag are recorded: intermediate hops are not exposed by fetch and are never invented. DNS, TLS and connection failures surface as one TypeError, reported as "Network error (not proof the link is dead)".
8. **Duplicate tiers.** High-confidence union-find covers only identical, normalized (scheme/host case, default port, empty `?` or `#`, IDN punycode) and documented tracking-parameter variants. Redirect and canonical evidence produce pairwise suggestions only. Convergent destinations are discarded: login, error and home pages, more than 4 units, or 3 or more sites converging. Canonicals are ignored when overbroad (root canonical on a deep page) or cross-site.
9. **Taxonomy discovery.** There is a staged pipeline (`src/core/discovery`, `src/core/ai/pipeline.ts`): full inventory, then a stratified sample (area × script language × weak title, square-root allocation, site round-robin, deterministic seed), then batched discovery against a single global candidate list with synonym merging, then hierarchy synthesis with strict validation and a deterministic fallback, then an editable draft, then a frozen, versioned taxonomy with stable IDs. The offline baseline uses a multilingual subject lexicon (`src/core/taxonomy/lexicon.ts`) as evidence vocabulary only.
10. **AI providers.** `auto` (the default) is the free on-device Chrome AI when it reports `available`, otherwise offline rules. It never selects the cloud. `chrome-ai` and `gemini` (BYOK, opt-in, after a consent screen listing exactly which fields are sent) are explicit choices. Model output is validated against allowlisted category IDs and batch indices, and anything malformed, unknown or duplicated is rejected. Bookmarks are referenced by local indices, never by Chrome IDs. URLs are redacted: host plus path, with queries, fragments, credentials and ID-like segments removed. Budgets on requests, tokens and estimated cost stop jobs gracefully with a `JobPause`.
11. **Mutation safety.** A write-ahead journal (`src/core/journal.ts`) persists intents before API calls. After a crash it reconciles by inspecting the live tree. Expected-state prechecks turn concurrent edits into conflicts. Generated-folder creation adopts an existing equivalent folder. Own-operation recognition is persisted and matched by *expected effect* (target parent, values), so later user moves are never mistaken for LinkSpruce's own. Bulk operations take a verified full snapshot first: written, read back and count-checked. Undo builds an inverse batch that restores items in ascending original index per folder and removes generated folders only if they are empty.
12. **Auto-filing.** Bookmark listeners are registered at the top level. A persisted queue applies a settle period, re-reads the bookmark before classifying and again before moving, and holds bursts and imports for review. Sync arrivals (older `dateAdded`) are left for review by default. A manual move becomes an override. A single-item journal plus periodic verified snapshots (every 50 operations or 7 days) protects each move. Category creation is subject to policy: daily cap, depth, top-level allowance and equivalence search. It is additive, so it bumps `version` (which invalidates bulk plans) but not `breakingVersion`.

## Known platform limitations

- Chrome doesn't identify who created a bookmark (user, sync, another extension), and LinkSpruce uses heuristics. Local locks can't coordinate devices: filed bookmarks are never re-filed automatically, which prevents oscillation.
- Undo cannot restore original bookmark IDs or `dateAdded`. Recreated items get new IDs.
- Prompt API language support is officially en, ja, es, de and fr. Persian and Arabic titles work, but less reliably on-device.
- The Interactions API is beta. `generateContent` is provided as a configurable fallback style.
